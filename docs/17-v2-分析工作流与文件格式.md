# 17 · v2 分析工作流、文件格式索引与公开源表

> 记录日期：2026-10-22  
> 状态：**v2 设计，不在 v1.0.0 中实现**  
> 原则：插件做**本地引导、格式解释、数据索引、可复现检查**；不把重型第三方程序偷偷打包，不绕过数据权限。

---

## 1. 目标

把“查文献/写作”扩展到“真正做分析”的入口：

```text
本地 FITS/事件表/能谱
  → DS9 看图像/头信息
  → 解释文件格式与关键字
  → 选择 3ML / AM3 / SED / 其他工具
  → 生成可复现命令与配置
  → 读取公开源表做交叉匹配
  → 记录版本、参数、数据来源
```

关键不是“插件里跑所有软件”，而是：

- 告诉初学者**这是什么文件、里面有什么、该用什么工具**；
- 给出**一步一步的本地操作**；
- 读取公开数据时**保留来源、版本、许可**；
- 不伪造光谱/能谱，不把模型当观测。

---

## 2. 第三方工具定位

| 工具 | 定位 | 插件怎么接 |
|---|---|---|
| **3ML** | 多仪器最大似然框架，支持 time-energy fit、joint fit、Fermi/XSPEC 插件 | 提供安装/版本检查、数据准备清单、模型配置模板、fit 结果解释；不内嵌整个 3ML |
| **AM³** | 轻子-强子时变多信使模拟（blazar/GRB/TDE），C++/Python/Docker | 提供安装/引用、参数表、运行示例、与观测 SED 对比流程；不内嵌模拟器 |
| **SED Builder (SSDC)** | 多波段 SED 构建/拟合的 Web 工具 | 提供使用步骤、导出格式解析、引用与数据来源记录；不抓取登录态页面 |
| **DS9** | FITS 图像/事件可视化 | 引导下载、打开本地 FITS、给出常用命令与头信息检查清单；不控制 GUI |
| **Geant4 / GENT4** | 粒子输运/探测器模拟（若 GENT4 指 Geant4） | 提供安装/版本/物理列表/输出格式说明；不运行重型模拟 |
| **公开源表** | Fermi 4FGL、3FHL、Swift/XRT、Chandra、XMM、Gaia、NED、SIMBAD 等 | 本地缓存 + 官方 TAP/VizieR 查询；标注版本/许可；不抓付费/登录数据 |

### 2.1 GENT4 需要确认

你写的是 **GENT4**。公开资料里常见的是 **Geant4**（CERN 粒子输运模拟）；也有同名/近似缩写工具。  
在实现前需要确认：

- 你指 **Geant4** 吗？
- 还是某个具体 GENT4 软件/论文/实验内部工具？

确认后再写安装、物理列表、输出格式和引用，避免把两个东西混为一谈。

## 3. 3ML：time-energy fit 工作流

参考：[3ML Time-energy fit](https://threeml.readthedocs.io/en/stable/notebooks/Time-energy-fit.html)

### 3.1 适合什么问题

- 同一个源在不同时间有多条能谱；
- 谱形（index/cutoff）基本不变，但归一化随时间变化；
- 需要联合多个仪器/多个时间段拟合；
- 需要比较模型（AIC/BIC、似然比）。

### 3.2 插件应提供的引导

1. **数据清单**：
   - 每个时间段的能谱文件（PHA/谱点/CSV）；
   - 仪器响应（RMF/ARF/IRF）；
   - 时间标签与单位；
   - 背景/前景模型；
   - 源位置与坐标历元。
2. **环境检查**：
   - Python 版本、3ML 版本、插件（Fermi/XSPEC）版本；
   - 不自动 `pip install` 重型包；给命令让用户在自己的环境执行。
3. **配置模板**：
   - `DataList` + `XYLike`/插件；
   - `IndependentVariable("time", ...)`；
   - 时间依赖模型（如 `Powerlaw`）链接到谱归一化；
   - `JointLikelihood` 配置。
4. **结果解释**：
   - 参数表、误差、相关性；
   - `-log(likelihood)`、AIC/BIC；
   - 不要只报“最佳拟合”，要报模型比较与系统误差。
5. **引用**：
   - 3ML 论文/版本；
   - 仪器数据论文/响应对应版本。

### 3.3 插件不做什么

- 不把 3ML 的完整输出当“物理结论”；
- 不自动下载用户没有权限的 Fermi/LAT 数据；
- 不伪造响应文件或时间标签；
- 不在没有数据时生成“示例结果”冒充真实分析。

## 4. AM³：多信使模拟工作流

参考：[AM³ documentation](https://am3.readthedocs.io/en/latest/)  
引用：Klinger et al., ApJS 275, 4 (2024), DOI `10.3847/1538-4365/ad725c`。

### 4.1 适合什么问题

- blazar / GRB / TDE 的轻子-强子时变模拟；
- 电子、正电子、质子、中子、光子、中微子、次级粒子的耦合；
- 电磁级联与强子反馈；
- 多信使（光子 + 中微子）参数扫描。

### 4.2 插件引导

1. 安装方式：Docker / native C++ / Python 接口；
2. 参数表：磁场、半径、质子/电子注入、谱指数、能量范围、时间步；
3. 运行前检查：单位、能量范围、粒子种类、输出变量；
4. 输出解释：光子 SED、中微子谱、次级粒子；
5. 与观测比较：SED Builder/3ML 拟合结果与模型对比；
6. 引用与版本：AM³ 版本、物理开关、编译选项。

### 4.3 风险

- 模拟参数多、简并强；不能把一组参数当唯一解；
- 强子模型依赖未确定物理（加速效率、磁场、辐射场）；
- 中微子预测对参数敏感，必须给不确定度/参数扫描。

## 5. SED Builder（SSDC）

参考：[SED Builder](https://tools.ssdc.asi.it/SED/)、[教程](https://www.ssdc.asi.it/tutorial/SEDBuilder/SEDBuilderTutorial.html)

### 5.1 用途

- 从多个目录/服务取多波段数据点；
- 构建/拟合 SED；
- 导出数据表/图。

### 5.2 插件引导

- 输入：源名、坐标、历元、检索半径；
- 数据来源：每个点的目录/论文/仪器；
- 单位：频率/波长/能量、flux density/energy flux；
- 银河/河外消光改正；
- 导出格式：CSV/VOTable/图；
- 引用：SSDC、各目录、原始论文。

**不抓取需要登录的页面；不绕过版权/许可。**

## 6. DS9 与本地 FITS

参考：[SAOImageDS9](https://ds9.si.edu/)

### 6.1 插件应做的

1. **下载引导**：官方安装包/包管理器；不提供修改版；
2. **打开本地文件**：给 DS9 命令/菜单路径；
3. **头信息检查清单**：
   - `SIMPLE`, `BITPIX`, `NAXIS`, `NAXIS1/2`, `EXTNAME`
   - `BUNIT`, `BSCALE`, `BZERO`
   - `CTYPE1/2`, `CRPIX`, `CRVAL`, `CDELT`/`CD`
   - `EXPTIME`, `MJD-OBS`, `DATE-OBS`
   - 事件表：`EVENTS`, `GTI`, `HDUCLASS`
4. **显示检查**：缩放、拉伸、坐标网格、孔径/区域文件；
5. **后续**：把 DS9 区域/坐标/头信息交给分析工具。

### 6.2 不能做的

- 插件不能控制 DS9 GUI（除非用户自己配 XPA）；
- 不能把“看起来像源”当探测；
- 不能省略 WCS/单位/曝光时间检查。

## 7. 文件格式索引（像术语一样）

### 7.1 产品形态

- 侧栏新增「文件格式」页；
- 搜索框像术语本一样：输入 `FITS`、`PHA`、`XML`、`RMF`、`VOTable`、`ECSV`；
- 每条给：
  - 全称/别名；
  - 典型扩展名；
  - 二进制/文本；
  - 里面通常有什么；
  - 关键头关键字/字段；
  - 常用工具；
  - 常见错误；
  - 示例/官方文档；
  - 相关格式。

### 7.2 首批格式

| 格式 | 典型扩展名 | 说明 |
|---|---|---|
| FITS 主头/图像 | `.fits`, `.fit`, `.fts` | 天文学标准容器；图像/表/事件 |
| FITS BINTABLE | `.fits` | 表格扩展；事件表、源表、响应 |
| FITS 事件表 | `.fits` | `EVENTS` 扩展 + `GTI`；时间/能量/坐标 |
| PHA | `.pha`, `.pi` | 脉冲高度/能谱计数 |
| RMF | `.rmf` | 响应矩阵（能量重分布） |
| ARF | `.arf` | 有效面积 |
| IRF | `.fits`, `.fits.gz` | 仪器响应函数（Fermi/CTA 等） |
| Fermi LAT XML | `.xml` | **源模型**，不是事件数据 |
| ROI | `.reg`, `.fits` | 区域/感兴趣区 |
| WCS | 头关键字 | 世界坐标系统；不是单独文件 |
| VOTable | `.xml`, `.vot` | 虚拟天文台表格 |
| ECSV | `.ecsv` | 带 YAML 元数据的 CSV |
| HDF5 | `.h5`, `.hdf5` | 层次数据；需约定 |
| ASDF | `.asdf` | YAML 树 + 二进制数组 |
| NetCDF | `.nc` | 多维数组；CF 约定 |
| YAML/JSON | `.yaml`, `.json` | 配置/模型参数 |
| LaTeX/BibTeX | `.tex`, `.bib` | 论文/引用，不是数据 |

### 7.3 Fermi XML 特别说明

Fermi LAT 的 `.xml` 通常是 **模型文件**（源位置、谱模型、扩散背景），供 `gtlike`/`fermipy` 等使用；**不是事件列表**。  
常见错误：

- 把 XML 当 FITS 事件表打开；
- 忘记 diffuse/isotropic 模板；
- 源名/坐标/历元不一致；
- 谱参数单位错（cm⁻² s⁻¹ MeV⁻¹ vs keV⁻¹）；
- 没记录 Fermitools/IRF 版本。

### 7.4 工具设计

- `astro_file_format`：search/get/list，像 `astro_term_lookup`；
- 数据：`data/file-formats.seed.json`；
- 未来：`astro_fits_inspect`（本地 FITS 头/HDU 检查，优先 astropy；无 astropy 时给 `fitsheader` 命令）；
- 不上传用户 FITS；只在本地读。

## 8. 公开源表

### 8.1 首批目录

- **Fermi LAT 4FGL / 4FGL-DR4**：银河系/河外点源；
- **Fermi LAT 3FHL**：高能源；
- **Swift/XRT 目录**：X 射线源；
- **Chandra Source Catalog**：X 射线源；
- **XMM-Newton 目录**：X 射线源；
- **Gaia**：恒星位置/视差/自行；
- **SDSS**：光学星表/光谱；
- **NED / SIMBAD / VizieR**：交叉证认；
- 其他按需：2MASS、WISE、NVSS、FIRST。

### 8.2 接入原则

- 只走官方 API/TAP/VizieR，不抓登录态/付费页；
- 本地缓存带：目录名、版本、查询日期、坐标历元、许可/引用；
- 支持 CSV/VOTable/FITS 导入；
- 交叉匹配要报半径、误差、误配率；
- 不把“目录里有”当“物理关联”。

### 8.3 工具设计

- `astro_catalog_search`：本地缓存目录搜索；
- `astro_catalog_import`：导入用户下载的 CSV/VOTable/FITS；
- `astro_catalog_crossmatch`：按坐标/误差交叉；
- 默认不自动下载大表；用户确认后再拉。

## 9. 端到端工作流示例

### 9.1 本地 FITS → DS9 → 3ML

1. `astro_fits_inspect` 读 HDU/头；
2. DS9 打开，检查 WCS/曝光/单位；
3. 用 DS9 画区域，导出 `.reg`；
4. 准备 PHA/RMF/ARF 或谱点；
5. 3ML 配置：DataList、时间标签、模型；
6. 拟合，输出参数/误差/模型比较；
7. 写分析记录：数据版本、响应版本、参数、图。

### 9.2 SED Builder → 插件

1. SED Builder 检索源；
2. 导出 CSV/VOTable；
3. `astro_catalog_import`/`astro_sed_import` 读入；
4. 检查单位、消光、历元；
5. 与 AM³/3ML 模型对比；
6. 引用每个数据点来源。

### 9.3 AM³ → 多信使

1. 安装 AM³（Docker 推荐）；
2. 参数表；
3. 运行光子/中微子输出；
4. 与 SED/观测上限对比；
5. 参数扫描与不确定度；
6. 记录版本/开关。

## 10. 安全、许可与可复现

- 第三方工具**不打包**进插件；只给安装/版本/命令/引用；
- 不自动执行从网上下载的脚本；
- 不绕过数据专有期/登录/付费；
- 用户 FITS/能谱默认本地，不上传；
- 每条分析记录：数据来源、版本、响应、工具版本、参数、日期；
- 重量级计算由用户环境执行；插件只做引导/配置/结果解释；
- 对“源表里有这个源”与“这个源有物理关联”严格区分。
