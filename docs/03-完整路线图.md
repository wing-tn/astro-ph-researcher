# 完整路线图：从术语卡到天文研究工作台

> 本文描述整个插件（不只第一步）的目标架构与阶段划分。
> 第一步 v1.0.0 已完成「术语核验 + 离线词表 + 同名词条消歧 + 文献检索 + 参考文献库 + 写作工作台 + 数据处理方法库 + 观测设备/数据工作流 + 8 个 skill」，是下面所有阶段的地基。

---

## 1. 最终目标

让天文学专业的学生与研究者可以在 DSH 内完成一条闭环：

```
读英文文献
  → 查/学专业术语（NADC 审定译名）
  → 检索 SCI 英文期刊 + 知网学位论文
  → 把选中文献交给 DSH 深入分析（方法/数据/公式/局限）
  → 导入自己的观测/模拟/计算结果
  → 依据可查询的文献与物理/天文原理生成 Python 分析代码
  → 用 LaTeX/Overleaf 写英文期刊论文或中文学位论文
```

关键约束：
- **可核验**：每个术语有 NADC 链接，每个结论有 DOI。
- **可复现**：检索式、数据、代码、参数、随机种子可导出。
- **不越权**：不抓取付费全文、不绕过知网登录、不伪造引用。
- **角色自适应**：本科生/研究生/研究员/教授的深度不同。

## 2. 阶段划分

### 阶段 1（v0.1.0 → v1.0.0）：术语、文献、写作与数据入口

- NADC 查词、相关术语、词条链接、审定状态/依据/定义
- 同名词条消歧（senses / alternatives / 按 astrodictId 切换）
- 官方全量离线词表（用户主动下载，约 31,758 条，断网兜底）
- 本地术语本（保存/搜索/导出 Markdown/CSV/Anki）
- 参考文献库（前三位作者/ORCID、单位、卷期页、DOI/SciX/ADS/arXiv、总结/关键结果、标签、BibTeX/APA/GB 7714/MLA）
- 写作工作台（期刊/学位论文项目、目标格式、多文件上传、分析/大纲/逐节起草/格式检查）
- 数据处理方法库（34 方法 + 9 统计 + 独立 Python 示例，版权安全版无书籍元数据）
- 观测设备/数据工作流库（30 个设施/项目、开放/受限/闭源、在建/规划）
- 4 个随包 skill（文献研究/代码/英文期刊/博士论文）

### 阶段 2（v0.2–v0.3）：读得更深

0. **NADC 离线词表增量维护**
   - 基础版已实现：官方 zip（r241020，约 696 KB）解析为 `en2zh / zh2en / abbr` 索引，约 31,758 条。
   - 下一步：ETag/Last-Modified 版本检查、增量更新、条目数校验。
   - 许可允许集成但禁止修改内容或与其他词库整合后二次发布：**不打包进发行物**，首次使用时从官方下载并署名。
   - 在线详情页只用于补台湾名/定义/出版状态/依据，结果缓存 ≥30 天。
1. **全文接入**
   - 检测 `@a9i5k4/dsh-literature`：复用其 PDF 文本/阅读器，避免重复下载。
   - 本地 PDF 上传 → 抽取文本 → 按章节切分 → 摘要/方法/结果分别分析。
   - 明确区分“摘要分析”和“全文分析”。
2. **术语抽取与高亮**
   - 从英文摘要/全文中抽取候选术语，匹配本地词表 + NADC。
   - 点击术语弹词卡；一键保存。
   - 术语共现图：同一篇文章中出现的术语互相链接。
3. **个人结果导入**
   - CSV/TSV、FITS 头信息、图片（光谱/光变曲线/图像）。
   - 生成“数据字典”：列名、单位、缺失值、样本量。
   - 把数据摘要作为后续代码生成与论文写作的上下文。
4. **知网题录解析**
   - 支持粘贴 CNKI 导出的 RefWorks/EndNote/NoteExpress 文本 → 结构化文献卡。
   - 不抓取、不绕过登录。

### 阶段 3（v0.4–v0.5）：算得出来

1. **文献 → 方法卡**
   - 从摘要/全文中抽取：样本、仪器/波段、方法、假设、公式、软件。
   - 每条方法卡附 DOI 与页码（若有全文）。
2. **Python 代码生成**
   - 基于方法卡 + 用户数据字典，生成 astropy/numpy/scipy/matplotlib 代码。
   - 强制：单位检查（astropy.units）、常数来源、随机种子、输入校验、结果图。
   - 代码头部写“依据文献 DOI + 公式来源”；不把未验证公式写成事实。
   - 在 DSH 沙箱/工作区运行测试，输出可复现脚本。
3. **物理一致性检查**
   - 量纲、数量级、边界条件（如光度不能为负、红移 z>-1）。
   - 与文献报告值对比，标出偏差。

### 阶段 4（v0.6+）：写得出来

1. **BibTeX / 引用**
   - 从 DOI/Crossref 生成 BibTeX；术语本导出术语表。
   - 在 DSH 中插入 `\cite{}`、生成参考文献。
2. **LaTeX / Overleaf**
   - 期刊模板脚手架（ApJ/A&A/MNRAS 等）；中文学位论文模板。
   - 生成 `main.tex`、`refs.bib`、图/表占位、编译说明。
   - Overleaf：生成可上传的 zip；不直接操作用户 Overleaf 账号（除非用户明确授权）。
3. **写作检查**
   - 英文语法/术语一致性（与术语本对齐）。
   - 数字/单位/引用完整性检查。
   - 图表 caption 与正文一致性。

## 3. 架构

```
┌──────────────────────────── Client (浏览器) ────────────────────────────┐
│ sidebar.footer.action → 浮窗（查词/文献/术语本/设置）                    │
│ shell.overlay → 浮窗渲染                                                  │
│ fetch /api/astro-ph-researcher/*                                                  │
└──────────────────────────────────────────────────────────────────────────┘
                                   │
┌──────────────────────────── Host (DSH Node) ────────────────────────────┐
│ tools: astro_term_lookup / save / list                                   │
│        astro_literature_search / analyze                                 │
│ routes: /api/astro-ph-researcher/{health,terms,lookup,search,analyze,export,...} │
│ services: NADC client, literature sources, ranking, store, handoff        │
│ storage: $DSH_HOME/astro-ph-researcher/{terms,config}.json                        │
└──────────────────────────────────────────────────────────────────────────┘
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        │                          │                          │
   NADC 天文学名词            OpenAlex / Crossref          NASA ADS / arXiv
   (HTML 检索)                (REST, 无 key)               (REST, token)
```

设计原则：
- **Host 负责网络与持久化**，Client 不直接跨域请求第三方（避免 CORS 与密钥暴露）。
- **工具与 HTTP 共用同一套业务函数**（`lookupTerm` / `searchLiterature` / `store`），避免两套逻辑漂移。
- **数据模型保留 provenance**：`translationSource`、`explanationSource`、`sourceUsed`、`fetchedAt`。
- **可选依赖降级**：ADS 无 token → OpenAlex；NADC 超时 → 本地词表；literature 插件不存在 → 独立 PDF 流程。

## 5. 代码生成阶段的硬约束（提前设计）

生成 Python 代码是这个插件最容易“看起来厉害但实际不可信”的部分。必须提前定规则：

1. **公式来源**：每个物理公式必须能追到文献 DOI 或教科书（作者/章节/页码）。
2. **单位**：优先 astropy.units；所有输入输出标注单位；量纲检查失败直接报错。
3. **常数**：用 astropy.constants 或明确数值 + 来源，不写魔法数。
4. **数据契约**：读取用户数据前先输出列名/单位/缺失值报告；不假设列名。
5. **可复现**：固定随机种子、记录包版本、生成 `requirements.txt`/`environment.yml`。
6. **测试**：至少一个合成数据测试 + 一个边界条件测试；运行失败不交付。
7. **不伪造结果**：代码可以运行但结果为空/异常时，如实报告，不生成假图。
8. **引用**：代码头部注释写“依据文献”和“公式出处”；论文中需引用对应文献。

---

## 6. LaTeX / Overleaf 阶段的硬约束

1. **模板**：优先官方期刊模板（ApJ/A&A/MNRAS）；中文学位论文用用户学校模板（需用户提供）。
2. **参考文献**：BibTeX 来自 Crossref/DOI；不手写条目；重复 DOI 去重。
3. **图表**：图片路径、分辨率、caption、编号可追溯；不生成假数据图。
4. **术语一致性**：正文术语与术语本对齐（英文/中文大小写、缩写首次定义）。
5. **Overleaf**：只生成 zip/工程文件；不代替用户登录、不自动提交。
6. **编译验证**：本地 latexmk/pdflatex 可用时编译；失败给出日志定位，不谎称成功。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| NADC 页面结构变化 | 查词失败 | 解析器单测 + 失败降级本地词表 + 明确提示 |
| NADC 词典许可 | 不能随插件分发 | 运行期从官方下载，展示署名/许可；不打包 zip |
| OpenAlex 计费/401 | 检索失败 | key（可选）+ 401 自动降级 Crossref/arXiv + UI 显示额度 |
| 引用数口径不一致 | 排序误导 | 显示来源与日期；不跨库混用 |
| 摘要不足以支撑结论 | 分析过度 | 模板强制“摘要未提供”；全文阶段再放开 |
| 代码生成幻觉公式 | 研究错误 | 公式必须追溯到 DOI/教材；单位与数值测试 |
| 知网合规 | 法律风险 | 只给链接/解析用户导出文件，不抓取 |
| 用户隐私 | 检索式泄露 | 设置页告知；不记录查询日志；token 只走环境变量 |
| DSH 版本升级 | slot/API 变化 | 只用稳定 slot；解析器与 API 版本化；兼容性测试 |

## 9. 与现有 DSH 插件生态的关系

- `@a9i5k4/dsh-literature`：文献库 + PDF 阅读 + 引用。阶段 2 优先复用，不重复造轮子。
- `dsh-python-env`：阶段 3 的 Python 环境与依赖安装。
- `dsh-ppt` / `dsh-univer-office`：组会/答辩/论文图表输出，可在阶段 4 组合。
- `dsh-diff-approval`：代码/论文修改审阅。
- `dsh-remote`：远程/移动端访问时的兼容性需单独测试（当前路由限 loopback）。

---

## 10. 结论

第一步把“术语可信、文献可解释、分析可控”这三件事做成可运行、可测试、可导出的地基。后续阶段都应遵守同一个原则：

> **任何模型输出都必须能落回一个可点击的来源；落不回去的，就标“未验证”。**
