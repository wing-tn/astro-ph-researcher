# 13 · 正式发布与打赏

## 1. v1.0.0 发布包

```text
dist/astro-ph-researcher-1.0.0.zip
dist/astro-ph-researcher-1.0.0.tar.gz
dist/SHA256SUMS
dist/RELEASE_NOTES.md
```

本地构建：

```bash
python scripts/make-release.py
sha256sum -c dist/SHA256SUMS
```

GitHub Release 上传 zip/tar.gz/SHA256SUMS/RELEASE_NOTES；不要把 `.venv/`、`provenance/raw/` 或本机路径放进 release zip。

## 2. GitHub 仓库命名

建议：

```text
https://github.com/hyperskysail/astro-ph-researcher
```

仓库名与包名一致，便于：

- DSH bundle 安装；
- Codex marketplace `astro-ph-researcher-local`；
- `FUNDING.yml` 指向 `SUPPORT.md`；
- 问题模板/更新日志/版本号对应。

## 3. 打赏：可以做，但要满足以下边界

**可以做：**

- 在 README / SUPPORT.md 放“自愿支持”入口；
- 微信/支付宝**个人收款码**图片（不要公开手机号/身份证/银行卡）；
- GitHub `.github/FUNDING.yml` 的 `custom` 指向一个 HTTPS 支持页面（`SUPPORT.md` 或 GitHub Pages）。

**不要做：**

- 不要写“付款后解锁功能/优先审稿/优先支持”；
- 不要冒充慈善募捐/公益项目（除非完成相应登记）；
- 不要用个人码收单位/机构款项或承诺开票；
- 不要把打赏说成购买服务、保证交付或保证服务器 SLA；
- 不要在仓库公开身份证、家庭住址、银行卡、手机号。

**微信/支付宝“链接”问题：**

- GitHub `FUNDING.yml` 只接受 URL，不接受二维码图片；
- 微信/支付宝个人收款码更适合作为图片放在 `SUPPORT.md`/GitHub Pages；
- 若你有官方商户支付链接，可把 HTTPS 链接放进 `SUPPORT.md` 的按钮；不要伪造支付页面。

**税务/合规（非法律建议）：**

- 个人打赏可能涉及个人所得税（偶然所得/劳务报酬/经营所得等，视当地认定）；
- 金额较大、持续收款或以单位名义收款时，建议咨询当地税务/法律专业人士；
- 平台（微信/支付宝/GitHub）各有收款、赞助、推广条款；发布前自行确认。

**服务器：**

- 当前插件**本地优先**，不需要服务器；打赏用于维护/数据更新/测试设备；
- 如果未来提供可选的在线索引/镜像，需单独写隐私、数据来源、服务条款与费用，不要偷偷把本地功能搬到付费墙后。
