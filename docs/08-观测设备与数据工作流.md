# 08 · 观测设备与数据工作流库

> 数据文件：`data/instruments.seed.json`
> 目标：把全球主要天文望远镜、观测卫星、地面探测器、引力波/中微子设施的数据获取与官方分析入口集中到侧边栏，并区分开放、受限、闭源与在建/规划状态。
> 当前覆盖：30 个设施/项目（运行 18、调试 2、在建 3、规划 4、提案 2、已结束 1；开放 22、专有期 4、受限 4）；25 条 `verified:true`，5 条因官网不可用/反爬标 `false`。逐 URL 实测记录见 [`research/instruments.md`](../research/instruments.md)。

---

## 1. 为什么单独做设备库

天文数据分析的第一道门槛往往不是算法，而是：

- 数据到底在哪个归档？CSC、HEASARC、UKSSDC、GWOSC、IceCube 数据中心的入口不同。
- 官方分析软件是什么？CIAO、HEASoft、fermipy、SkyLLH、GWpy/PyCBC 的安装和版本要求不同。
- 数据政策是什么？开放、专有期、申请制、闭源合作，决定能不能直接下载。
- 在建/规划项目现在有没有数据？不能把“未来设施”当成“现在可分析”。

设备库把“设施 → 数据 → 软件 → 工作流 → 政策建议”放在一张卡片里。

## 3. 覆盖范围

### 运行中/开放或半开放

Chandra、Fermi-LAT、Fermi-GBM、Swift、XMM-Newton、NuSTAR、JWST、Hubble、Gaia、TESS、ALMA、VLA、IceCube、LIGO/Virgo/KAGRA、H.E.S.S.、Pierre Auger、eROSITA/SRG。

### 受限/闭源（用户点名）

FAST、LHAASO、IXPE：给官方数据申请/合作政策、分析建议与链接；不把它们标成“开放下载”。

### 在建

CTAO、SKA、Rubin/LSST、ELT、TMT、ngVLA。

### 规划/未立项

Athena、LISA、IceCube-Gen2、eXTP。

> 状态以调研时官方页面为准；`verified:false` 表示链接/政策未能在本机在线验证，UI 会提示。不要在论文中把规划设施当成已运行数据源。

## 4. 典型工作流

### 4.1 X 射线：Chandra / XMM / Swift / NuSTAR

1. 在官方归档检索目标与曝光（CSC / HEASARC / UKSSDC）。
2. 下载事件列表、响应矩阵、辅助文件与校准数据。
3. 用 CIAO 或 HEASoft 做筛选、校准、背景估计、谱拟合。
4. 记录软件版本、校准版本、筛选条件；引用观测编号与 DOI。
5. 开放数据注意专有期；闭源/申请数据先写申请理由与可行性。

### 4.2 高能/伽马：Fermi-LAT / GBM

- LAT：fermipy + FSSC 文档，做 ROI 拟合、弥散背景、能谱/光变。
- GBM：HEASoft/GBM 数据工具，做触发/谱分析；注意定位误差与地球遮挡。
- 与多波段/多信使联测时，统一时间基准（MET/UTC）与坐标框架。

### 4.3 中微子：IceCube

- 数据：IceCube 数据中心（公开事件、IRFs、有效面积）。
- 分析：SkyLLH（Python）做点源/堆叠/时间依赖搜索；或官方示例流程。
- 注意：事件重建误差、大气中微子背景、盲分析策略、试验因子。

### 4.4 引力波：LIGO/Virgo/KAGRA

- 数据：GWOSC（应变、事件参数、功率谱）。
- 分析：GWpy（读取/滤波/时频）、PyCBC（匹配滤波/参数估计）。
- 注意：校准不确定度、glitch、信号一致性、盲注入。

### 4.5 射电：FAST / ALMA / VLA

- FAST：数据政策以官方为准；申请/合作项目按 PI 流程；分析用 astropy/radio 工具与团队管线。
- ALMA/VLA：NRAO/ALMA 归档开放；CASA 管线；注意校准与成像参数。
- 不能把 FAST 的观测数据当成公开归档直接下载。

### 4.6 在建/规划

- CTAO/SKA/Rubin/ELT/TMT/ngVLA：关注官方数据政策、早期科学、软件与数据格式；当前用公开路径/模拟数据。
- Athena/LISA/IceCube-Gen2/eXTP：规划阶段，不能声称已有数据；可跟踪官方白皮书/任务页面。

## 5. 插件操作

- 侧栏「数据」→「观测设备/数据」。
- 搜索设施；按运行状态/数据政策筛选。
- 点官方数据/分析链接；查看软件、工作流、建议。
- 「保存为我的工作流」写入本地 `workflows.json`。
- 「交给 DSH 设计/检查流程」把设施、链接、步骤注入当前对话，让 DSH 生成可执行方案；无活跃对话时复制提示词。

工具：
- `astro_data_method`：方法/统计/Python 示例。
- `astro_data_instrument`：设备/数据/软件/工作流。
- `astro_data_workflow`：list/save/delete 个人工作流。

HTTP：
- `GET /api/astro-ph-researcher/data/meta`
- `GET /api/astro-ph-researcher/data/methods`
- `GET /api/astro-ph-researcher/data/instruments`
- `GET/POST/DELETE /api/astro-ph-researcher/data/workflows`
- `POST /api/astro-ph-researcher/data/handoff`

---

## 6. 边界

- 只提供官方入口与工作流建议，不代为申请数据、不绕过登录/付费墙/专有期。
- 不保证所有设施的数据政策永久不变；以官方页面为准。
- `verified:false` 的条目需要用户自行确认。
- 不在插件内执行完整分析管线；DSH 负责生成/检查方案，实际计算在用户环境。
- 论文引用设施时，按各设施官方致谢/数据 DOI 要求。
