# 第一步：术语核验 + 文献检索 + 分析转交

> 版本：v1.0.0（2026-10-22）
> 工作区：`F:\dsh插件\astro-words`
> 目标读者：天文学本科生、研究生、研究员、大学教授

---

## 1. 为什么第一步选这三个动作

天文学研究的工作流通常是：

```
读英文文献 → 遇到术语 → 查中文名/定义 → 找相关文献 → 判断值不值得读
→ 精读 → 记录 → 写代码/写论文
```

第一步不做“全自动读论文”，而是把**最频繁、最容易出错、最影响后续质量**的三个动作做扎实：

1. **术语查准**：中文译名有国家标准/名词委审定，不能让模型自由发挥。
2. **文献找对**：相关性、时间、引用数三个信号必须可解释、可切换。
3. **分析可控**：由用户明确选择“交给 DSH”，并且只基于可核验的题录/摘要，不让模型编造。

这三步也是后续“导入个人结果 → 生成 Python 代码 → LaTeX/Overleaf 写作”的入口：术语本、文献库、检索快照都是后续步骤的上下文。

## 2. 用户画像与场景

| 用户 | 典型任务 | 第一步最需要 | 不需要 |
|---|---|---|---|
| 本科生 | 课程论文、读综述、理解概念 | 权威中文名、通俗物理图像、入门综述 | 复杂检索式、ADS 高级语法 |
| 研究生 | 开题、组会、方法复现 | 方法与数据、公式、可复现清单、最新文献 | 教材式长解释 |
| 研究员 | 追领域进展、审稿、找合作 | 相关性 + 引用速度、ADS、去重、检索快照 | 过度简化 |
| 教授/教师 | 备课、指导、写综述 | 术语图谱、教学例子、综述优先 | 单篇深挖 |

因此插件把“面向人群”做成设置项，影响：
- 交给 DSH 的分析模板深度；
- 术语讲解的结构（本科生多物理图像，研究员多局限与可复现）；
- 默认检索排序（研究生/研究员可默认“相关”，教师可默认“高引综述”）。

## 4. 术语核验设计

### 4.1 NADC 页面事实

- 检索：`/astrodict/fuzzy?word=<词>`（不区分大小写的子串匹配，上限 100 行，**按字母序而非相关度**）与 `/astrodict/precise?word=<词>`（连续 token 前缀匹配）。**缩写必须走 precise**：`fuzzy?word=AGN` 会返回 100 条“AB magnitude”噪声。
- 结果表字段：外文名、缩写、语种、中文名；中文名可能用 `;` 分隔多个译名。
- 详情页：中文名、台湾名、出版状态（如“已出版”）、依据书目、最后修订日期、词源（常为空）。
- **部分词条带《天文学名词（定义版）》的“定义”字段**，另有“备注/范例/标签”；不是每条都有。
- 因此展示顺序固定为：**NADC 审定定义（原文，若有）→ DSH 释义（生成，明确标注）**，绝不把 DSH 释义写进定义字段。

### 4.2 匹配规则

1. 归一化：NFKC、大小写、连字符、标点、空白。
2. 精确匹配：英文名 = 1.0，中文名 = 1.0，缩写 = 0.97。
3. 强匹配：查询词是英文名的词根子集，或英文名是查询词的子集，0.80–0.94。
4. 近似匹配：Dice 字符相似度 + 词元 Jaccard，0.55–0.80。
5. 低于 0.55 不自动选择，返回候选让用户点选。
6. 中文查询若 NADC 无结果，回退本地词表；仍无则明确说“未收录”，不猜。

### 4.3 证据链

每个词条返回：

```json
{
  "astrodictId": "16171",
  "astrodictUrl": "https://nadc.china-vo.org/astrodict/termdetails?id=16171",
  "status": "已出版",
  "sources": ["《英汉天文学名词》…", "《天文学名词（第三版）》…"],
  "lastRevised": "2010-04-15",
  "definition": "(1) 天体谱线的观测波长向长波方向频移的现象。…",
  "definitionSource": "NADC《天文学名词（定义版）》",
  "notes": "",
  "examples": [],
  "nadcTags": ["天体物理"],
  "matchedBy": "exact",
  "verification": "nadc-live",
  "attribution": {
    "translationVerified": true,
    "explanationNote": "中文译名来自 NADC；DSH 释义为插件生成，不是名词委原文"
  }
}
```

UI 中三层信息视觉分离：
- **审定译名**（NADC，带链接和状态）
- **DSH 释义**（灰底段落，明确标注）
- **个人笔记**（术语本中单独字段）

导出 Markdown/CSV 时同样保留 `astrodictUrl` 与 `explanationSource`，避免二次传播时把 DSH 释义误当名词委原文。

### 4.4 同名词条消歧

NADC 的英文名/中文名不是一一对应：`gravitational lensing`、`gravitational lensing effect`、`weak gravitational lensing` 可能共享“引力透镜效应”这一中文名；`transit` 在天体力学里是“凌”，在系外行星语境常被译作“凌星”。

本版做法：
1. 每次查词保留 top 10 候选，计算 `senses`（英文名、中文名、id、链接、匹配度、是否当前）。
2. 额外返回 `alternatives`：与当前词条**中文名相同**或匹配度 ≥0.97 的候选。
3. UI 出现「同名词条 / 其他译名」，点击某个候选时用 `astrodictId` 直接打开该词条（不再依赖字符串重查）。
4. 保存术语本时记录 `astrodictId`，避免以后按中文名查找时串条。
5. 工具输出也会列出“当前/其他”，并提示用户确认。

这样既不会静默选错，也不会把“弱引力透镜/强引力透镜”这类相关但不同的词误当同义词。

### 4.5 官方全量离线词表

官方下载页提供 zip（当前 r241020）：
- `ec` 30,094 行（EN→ZH）+ `ce` 26,770 行（ZH→EN），UTF-8、TAB 分隔；
- 解析后约 31,758 条去重词条；缩写词条用 `全称：…。中文名` 表达；
- **没有 id、台湾名、定义、出版状态**；这些仍需在线详情页补全。

实现：
- 首次由用户点击“下载官方词表”才请求 zip，不在插件发行物里打包；
- 下载后解析为 `astrodict-dictionary.json`（约 4.5 MB）存于 `$DSH_HOME/astro-ph-researcher/`；
- 启动时加载一次，建 `byEn / byZh / byAbbr` 索引；
- 查词顺序：在线 NADC（拿 id/定义/状态）→ 失败/未命中时用离线词表兜底；
- 离线命中返回 `verification: "offline-dictionary"`，链接指向 NADC 检索页，并提示“联网后补全定义”。

**许可**：所有权归中国天文学会；允许集成、二次开发、格式转换，但不得修改内容或与其他词库产品整合后二次发布。因此只做“用户主动下载到本地”，不把 zip/解析结果放进 npm 包。

## 5. 文献检索与排序

### 5.1 检索式

- 主检索字段：OpenAlex `title_and_abstract.search`，避免全文检索把材料学、生物学论文带进来。
- 过滤：`is_retracted:false`、类型（article/review/preprint）、年份、最低被引、OA。
- 中文查询：先 NADC 反查英文名；命中则自动转英文，未命中则提示用户先查词，不机器硬翻。
- 来源优先级：ADS（有 token）→ OpenAlex → Crossref。arXiv 作为显式来源或补充。

### 5.2 排序公式

默认「综合」：

```
rel   = relevance_score / max(relevance_score)          # 0..1
time  = 0.5 ^ (age / halfLifeYears)                     # 半衰期默认 8 年
cite  = log1p(citations) / log1p(max(citations))        # 0..1
score = 0.60 * rel + 0.25 * time + 0.15 * cite
```

为什么这样定：
- **相关性 0.60**：用户要的是“和这个问题有关”，不是“最热”。
- **时间 0.25**：天文学中 1990 年代的基础论文仍然重要，所以不用硬截断；半衰期 8 年意味着 8 年前权重减半。
- **引用 0.15**：引用数受领域规模、发表年限、自引影响，只能做次要信号；用 `log1p` 压缩长尾。
- 四个排序模式（综合/相关/最新/高引）都保留，用户可覆盖默认。
- **严格优先级模式**（可选）：把相关性按 5% 分档，档内先比时间、再比引用。这样“相关性差距 >5%”时，时间和引用无法翻盘，符合“相关性（主）> 时间（次1）> 引用数（次2）”的字面语义。默认关闭（加权分更平滑），设置页可开启。

### 5.3 去重与版本

- DOI 相同 → 合并。
- 标题归一化后完全相同 → 合并，保留引用数更高、 venue 更完整的版本。
- 合并时保留 arXiv / 开放 PDF / ADS / OpenAlex 链接，UI 每类只显示一个主链接。
- 当前不做模糊标题合并，避免把“同一系列第 I/II/III 篇”误合并（已踩过坑）。

### 5.4 每条结果的字段

- 标题、作者（前 6 + et al.）、年份、期刊、类型、引用数
- DOI / ADS / arXiv / OpenAlex / Scholar / 开放 PDF
- 摘要（截断 260 字用于卡片，完整摘要用于分析包）
- 评分分解：相关性 / 时间 / 引用
- 为什么相关：命中的检索词
- 标记：综述、高引、近 3 年、开放获取、预印本
- 来源与检索时间（用于复现）

## 6. 交给 DSH 的协议

### 6.1 触发方式

- 单篇：「分析这篇」
- 多篇：勾选 → 「交给 DSH 分析所选」
- 术语：「交给 DSH 讲解」/「在对话中搜索」

### 6.2 Host 端注入

```js
const agent = ctx.agents.get(sessionId);
const { createUserMessage } = await import('@deepseek-ai/dsh-llm');
agent.steer(createUserMessage({
  content: [{ type: 'text', text: prompt }],
  source: { kind: 'user' }
}));
```

- 只注入到**当前活跃会话**，不新建会话、不抢焦点。
- 当前无活跃会话 → 返回 409 + 提示词，前端复制到剪贴板。
- 注入的是“用户消息”，因此在对话历史中可追溯、可编辑、可继续追问。

### 6.3 分析模板的硬约束

1. 只用给定题录/摘要；缺失写“摘要未提供”，不得编造数据。
2. 区分“论文原文”与“推断”，推断标【推断】。
3. 关键结论附 DOI。
4. 公式给符号、单位、适用条件。
5. 输出可复现性清单（数据、代码、参数、随机种子、软件版本）。
6. 按角色调整深度（本科生/研究生/研究员/教授）。
7. 最后给 3–5 个下一步英文检索词。

## 7. 本地数据与隐私

| 数据 | 位置 | 是否上传 |
|---|---|---|
| 术语本 | `%USERPROFILE%\.dsh\astro-ph-researcher\terms.json` | 否 |
| 配置 | 同目录 `config.json` | 否 |

| 术语查询 | 发往 NADC 网页 | 是（仅查询词） |

- 不读取用户会话内容，除非用户点「在对话中搜索」并显式让 DSH 调用 `session_search`。
- 不抓取知网登录态内容。

## 9. 第一步还能怎么优化（重点）

下面按“对天文学者的实际便利”排序，分为**本版已做**、**建议下一步做**、**暂不做**。

> 实现过程中已经落实的一条高价值优化：**解析 NADC 详情页的“定义/备注/范例/标签”字段**，把《天文学名词（定义版）》原文作为最高优先级展示，再接 DSH 释义。这比任何排序技巧都更直接地提升“查词可信度”。

### 9.1 最值得做的 8 件事

| # | 优化 | 为什么对天文学者重要 | 成本 | 建议 |
|---|---|---|---|---|
| 1 | **综述优先模式** | 本科生/转方向的研究者最需要“先读 1 篇综述再读 10 篇论文”；综述能快速给出领域地图 | 低 | P0：加“只看综述/综述优先”开关，利用 OpenAlex `type:review` + 标题含 review 的启发式 |
| 2 | **引用速度而不只是总引用** | 1995 年 1000 引和 2023 年 300 引不是一回事；天文学新论文 2–3 年就能到几百引 | 低 | P0：显示 `cites / age`，加“新星”标记；排序可选“引用速度” |
| 3 | **术语消歧（多译名/多词条）** | 同一英文词可能对应多个 NADC 词条（lens vs lensing；redshift vs cosmological redshift），静默选一个会误导 | 中 | v0.3.0 已做基础版：senses + alternatives + 按 id 切换；下一步做“中文多译名/教材语境”提示 |
| 4 | **从摘要抽取术语并链接 NADC** | 读文献时最痛的是“这一段每个词都要查”；自动高亮候选术语可把查词成本降到一次点击 | 中 | P1：用本地词表 + NADC 匹配做候选高亮；点击弹词卡 |
| 5 | **检索快照/可复现** | 研究员需要下次复现同一检索；学生写论文需要说明“文献怎么找的” | 低 | P0：导出检索结果时记录 query、sort、filters、source、timestamp、API 版本 |
| 6 | **ADS 接入与引用口径提示** | ADS 是天文学事实标准；不同库引用数能差 20%+，必须让用户知道口径 | 中 | P1：已支持 token；下一步显示“引用数来源：ADS/OpenAlex，截至日期” |
| 7 | **术语本 → Anki / 复习** | 学生背术语的需求真实存在；导出 Anki 比复制到笔记本更可用 | 低 | 已做基础导出；下一步加“只导出未掌握/带标签” |
| 8 | **与 `dsh-literature` 联动** | 用户已装文献插件；重复保存/重复下载 PDF 很烦 | 中 | P2：检测到 literature 插件时，提供“保存到文献库/打开 PDF”而不是复制一套 |

> v0.3.0 已额外完成：**官方 NADC 全量离线词表**（用户主动下载，约 3 万条，断网兜底）+ **同名词条消歧基础版**（senses/alternatives/按 id 切换）。

### 9.2 检索质量（P0–P1）

1. **主题过滤**：OpenAlex `primary_topic.field.id:31`（Physics and Astronomy）可减少跨领域噪声，但会漏掉行星科学（Earth and Planetary Sciences, 19）与部分太阳物理。建议做成“天文/物理优先”开关，而不是硬过滤。
2. **综述识别**：`type:review` 之外，标题含 `review`、`overview`、`progress report`、`annual review` 也算；但不要把“review of X method”误判为领域综述。
3. **预印本与正式版合并**：用 arXiv ID + DOI + 标题精确匹配；不要模糊合并（会误合并系列论文）。
4. **作者/机构检索**：天文学者常按作者（如 "EHT Collaboration"）或巡天项目（SDSS、Gaia、JWST）检索；下一步加 `author`、`institution`、`keyword` 高级过滤。
5. **ADS 语法兼容**：研究员习惯 `abs:"..." author:"..." year:2020-2024`；可在设置中允许“ADS 模式”直接透传检索式。
6. **引用数归一化**：不同领域引用基线差异大（宇宙学 vs 太阳物理）；可用 OpenAlex `cited_by_percentile_year` 或同子领域分位数替代绝对数。这是一个高质量优化，但需要额外 API 字段。
7. **撤稿/勘误**：已过滤 `is_retracted:false`；下一步显示“有勘误/撤稿”标记。
8. **中文文献**：知网无 API；可支持“粘贴 CNKI 导出题录 → 解析为文献卡”，比爬取合规且实用。Crossref 的 `query.bibliographic` 对中文题录意外可用，可作为中文期刊元数据的合法补充路径（学位论文仍需知网）。
9. **SCI 收录判定**：OpenAlex/Crossref 没有 SCI 收录字段。当前用“article/review + 期刊来源 + 引用数”近似，不声称 SCI 收录；严格名单需要 Web of Science/Scopus 授权或自建期刊白名单。这是“查 SCI 期刊”需求必须提前说明的边界。
10. **OpenAlex 额度与 401**：2026 年起 OpenAlex 改为计费模型，无 key 按 IP 共享约 $0.10/天，检索约 $0.001/次；额度耗尽返回 HTTP 401。本版已做 401 → Crossref 自动降级；下一步在 UI 显示剩余额度（响应头 `X-RateLimit-Remaining`）与“配置 key”引导。
11. **缩写查询走 precise**：`fuzzy?word=AGN` 会返回 100 条噪声（AB magnitude 等）；本版已对全大写缩写优先走 `precise`。下一步把“缩写 → 全称 → 中文名”做成术语卡上的独立字段。

### 9.3 术语学习（P0–P2）

1. **中文反查英文**：已支持；但任意中文短语（“星系团引力透镜”）仍可能查不到。下一步用 NADC 分词 + 本地词表组合匹配，给出“可能的英文检索式”。
2. **词根拆解**：`astro-`、`photo-`、`spectro-`、`-metry`、`-sphere` 等前缀/后缀解释，对本科生非常友好；可与术语卡并列展示。
3. **术语图谱**：把“相关术语”从字符串相似度升级为“文献共现 + 概念层级”（如 引力透镜 → 强/弱/微引力透镜 → 宇宙剪切）。这需要构建本地图数据，属于第二步。
4. **教材映射**：把术语映射到常用教材章节（如 Carroll & Ostlie、Ryden、Binney & Tremaine），学生可知道“去哪本书补”。版权允许的话只存章节号，不存正文。
5. **多语言**：台湾名已显示；下一步加英文释义（面向国际学生/合作者）。
6. **发音/缩写**：AGN、CMB、SFR、IMF 等缩写常被读错/写错；术语卡加“全称 + 缩写 + 常见误写”。
7. **定义版本**：NADC 有《天文学名词（定义版）》（2001），部分词条详情页已有“定义”字段。本版已解析并原样展示；下一步争取全量/结构化数据，并标注定义版年份。这是最值得向 NADC 争取的数据。

### 9.4 工作流与 UI（P1–P2）

1. **全局快捷键**：`Ctrl/Cmd + K` 打开查词，`Esc` 关闭；侧边栏按钮不是最快入口。
2. **选中文本查词**：在对话/文献摘要中选中英文术语 → 右键/浮标“查 NADC”。DSH 客户端可以通过 DOM 事件实现，但要注意不干扰宿主。
3. **多标签/并排**：查词与文献同时可见；当前是 tab 切换，研究者可能想边看词卡边看论文列表。
4. **拖拽/粘贴 DOI**：把 DOI/arXiv ID 拖进面板 → 直接解析为文献卡；比输入检索式快。
5. **结果密度**：研究员希望一屏 10 条；学生希望一屏 3 条带摘要。可加“紧凑/舒适”密度开关。
6. **双语界面**：目前中文；国际学生/合作者需要 English UI。
7. **可访问性**：键盘导航、屏幕阅读器标签、色弱友好（当前颜色有品牌色/成功/警告区分，仍需检查对比度）。
8. **移动端/窄屏**：当前窄屏全宽；下一步做底部抽屉。

### 9.5 可信度与防幻觉（P0）

1. **引用必须可点**：所有结论必须能落到 DOI/NADC 链接；分析模板已强制，但 UI 还应显示“未提供 DOI”的警告。
2. **“未验证”标签**：用户自建词条、无 NADC id 的术语，术语本和导出都应标“未核验”，避免被当成审定译名。
3. **DOI 存在性校验**：保存文献/导出引用前，用 Crossref `works/{doi}` 快速校验；失败则标“DOI 可能失效”。
4. **摘要边界**：明确告诉用户“当前只基于摘要，不是全文”；避免把摘要没写的结论说成论文结论。
5. **可追溯的模型行为**：分析包保留“使用了哪些文献/哪些字段”，用户可复核。
6. **不要把 DSH 释义写进“审定译名”字段**：数据模型已分离 `translationSource` 与 `explanationSource`；后续任何导出/同步都要保持。

### 9.6 性能与离线（P1）

1. **NADC 全量离线索引（已实现）**：官方提供词典下载页（`/astrodict/article/download`），当前 zip 为 r241020（约 696 KB，EN→ZH 30,094 行、ZH→EN 26,770 行，UTF-8 两列 TSV；无 id/台湾名/定义）。设置页一键下载后解析为约 31,758 条本地索引，查词毫秒级；不随插件打包。
   - **许可红线**：所有权归中国天文学会；允许集成、二次开发、格式转换；**不得修改内容，或与其他词库产品整合后二次发布**。因此只做“用户主动从官方 URL 下载到本地”，并展示署名与许可。
   - 需要台湾名/定义/出版状态时再走在线详情页（并缓存 30 天）。
   - 下一步：版本检查（ETag/Last-Modified）、增量更新、词表完整性校验。
2. **请求合并/缓存**：已做 24h 内存缓存 + **1 请求/秒**限速；下一步持久化缓存到磁盘，重启不丢。
3. **预取**：打开词卡时预取相关词条详情；打开文献 tab 时预取默认检索。
4. **超时降级**：NADC 超时 → 本地词表；OpenAlex 超时 → Crossref；UI 显示“降级来源”。

### 9.7 合规与隐私（P1）

1. **NADC 使用条款**：只做低频率检索（**1 请求/秒**），带明确 User-Agent；不批量爬取、不重建数据库（除非官方许可）。
2. **种子数据的许可边界**：为离线体验，当前 `data/terms.seed.json` 含 21 条 NADC 定义原文与 29 条审定译名。NADC 许可允许集成/格式转换，但**禁止修改内容或与其他词库整合后二次发布**。本仓库是本地原型；**公开发布前应改为运行期从官方 zip 下载，或删除逐字定义、只保留链接与 DSH 自写释义**。
3. **知网**：坚持只给人工链接；不做登录态抓取、不绕过付费墙。
4. **ADS token**：只从环境变量读取，不写 JSON、不进日志。
5. **检索式隐私**：检索式会发给第三方 API；设置页明确告知，允许关闭。
6. **遥测**：不收集用户查询、不埋点、不上传术语本。

### 9.8 与完整插件路线图的衔接

第一步刻意不做、但已预留接口的：

- **全文分析**：`astro_literature_analyze` 目前只吃摘要；第二步可接入 `dsh-literature` 的 PDF 文本或本地 PDF，增加 `fullText` 字段。
- **个人结果导入**：第二步加 `astro_import_result`（CSV/FITS/图片），把数据摘要作为分析上下文。
- **Python 代码生成**：第三步基于“文献方法 + 物理公式 + 数据格式”生成可运行代码（astropy/numpy/matplotlib），并强制引用来源与单位检查。
- **LaTeX/Overleaf**：第三步支持 BibTeX 导出、`\cite{}` 插入、期刊模板脚手架、Overleaf 项目链接。
- **知网学位论文**：第二步支持“粘贴 CNKI 导出题录 → 结构化”；不做抓取。

## 11. 一句话总结

第一步的价值不是“又一个查词/搜论文工具”，而是：

> **把“审定译名—可解释排序—可控分析”串成一条可追溯的链路，让天文学者敢用、能复核、愿意长期积累自己的术语与文献库。**

当前版本已经把这条链路跑通；上面 9.1 的 8 件事是让它从“能用”变成“离不开”的关键。
