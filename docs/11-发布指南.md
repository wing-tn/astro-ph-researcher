## 2. 上传 GitHub

### 2.1 创建空仓库

在 GitHub 新建：

```text
hyperskysail/astro-ph-researcher
```

不要勾选 “Add a README”（本地已有）。

### 2.2 本地初始化并推送

```bash
cd F:\dsh插件\astro-words

git init
git add .
git commit -m "feat: astro-ph-researcher v1.0.0 (DSH + Codex + intro PDF)"
git branch -M main
git remote add origin https://github.com/hyperskysail/astro-ph-researcher.git
git push -u origin main
```

### 2.3 打 tag / GitHub Release

```bash
git tag v1.0.0
git push origin v1.0.0
```

或直接用 GitHub CLI：

```bash
gh release create v1.0.0 \
  dist/astro-ph-researcher-1.0.0.zip \
  dist/astro-ph-researcher-1.0.0.tar.gz \
  dist/SHA256SUMS \
  --title "astro-ph-researcher v1.0.0" \
  --notes-file RELEASE_NOTES.md
```

在 GitHub **Releases → Draft a new release**：

- Tag：`v1.0.0`
- 附件建议：
  - `dist/astro-ph-researcher-1.0.0.zip`（正式发布包）
  - `dist/astro-ph-researcher-1.0.0.tar.gz`
  - `dist/SHA256SUMS`
  - `dist/RELEASE_NOTES.md`
  - `presentation/astro-ph-researcher.pdf`（介绍 PDF）
  - `provenance/astro-ph-researcher-v1.0.0-provenance-2026-10-22.zip`（创作证据；不要上传 raw session）
- Release 说明用 `dist/RELEASE_NOTES.md` 或根目录 `RELEASE_NOTES.md`。

网页：仓库首页 → About 右侧齿轮 → Topics → 添加 `dsh-plugin`、`astronomy`、`deepseek-harness`。

或用 `gh`：

```bash
gh repo edit hyperskysail/astro-ph-researcher --add-topic dsh-plugin --add-topic astronomy --add-topic deepseek-harness
```

## 3. 上架 DSH 插件市场

### 3.1 关键事实

**DSH 市场（dshmarket）不提供“上传插件文件”的后台。**  
它的目录来自 [`awesome-dsh-plugin/awesome-dsh-plugin`](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)，插件条目通过 **GitHub PR** 提交；合并后站点与 dshmarket 自动收录，通常一天内生效。

### 3.2 提交一个 YAML 文件

在 `awesome-dsh-plugin` 仓库新建：

```text
data/plugins/hyperskysail__astro-ph-researcher.yml
```

内容使用本仓库模板：

[`submission/awesome-dsh-plugin/hyperskysail__astro-ph-researcher.yml`](submission/awesome-dsh-plugin/hyperskysail__astro-ph-researcher.yml)

```yaml
url: https://github.com/hyperskysail/astro-ph-researcher
name: hyperskysail/astro-ph-researcher
category: tools
description:
  en: 'Astronomy workbench for DSH and Codex: NADC-validated terms, a local reference library, journal/thesis writing handoff with ten goal-aware styles, and a 30-facility data-workflow directory.'
  zh: '面向天文的 DSH/Codex 工作台：NADC 术语核验、本地参考文献库、期刊/学位论文写作交接（10 种目标感知风格），以及 30 个观测设施的数据工作流目录。'
```

- `description.en` 含冒号，必须用引号；模板已用单引号。
- 一个 PR 最多 3 条；你只提交这 1 条。
- 不要手工改 `README.md`；维护者会从 YAML 生成。
- 如果仓库名不是 `astro-ph-researcher`，把 `url` 和 `name` 改成实际值。

### 3.3 PR 前核对

```text
[ ] GitHub 仓库是 public
[ ] 仓库创建 ≥ 1 天
[ ] 已添加 topic: dsh-plugin
[ ] package.json 有 dsh.bundle.patch
[ ] 真实代码 + 可运行测试，不是 README-only
[ ] 描述不含营销词、数字能被代码核对
[ ] 没有把别人插件重新打包
```

### 3.4 提交 PR

```bash
git clone https://github.com/awesome-dsh-plugin/awesome-dsh-plugin.git
cd awesome-dsh-plugin
# 复制模板到 data/plugins/hyperskysail__astro-ph-researcher.yml
git checkout -b add-astro-ph-researcher
git add data/plugins/hyperskysail__astro-ph-researcher.yml
git commit -m "Add hyperskysail/astro-ph-researcher"
git push origin add-astro-ph-researcher
```

在 GitHub 开 PR。CI 会检查：

- 条目数 ≤ 3
- `package.json` 的 `dsh.bundle`
- 仓库年龄 ≥ 1 天
- `awesome-lint` / 站点生成

合并后，dshmarket 会从精选列表同步；通常一天内出现。

### 3.5 安装命令（用户侧）

上架后，用户可直接：

```bash
dsh plugin --profile desktop add astro-ph-researcher
```

如果没发 npm 包、只从 GitHub 安装：

```bash
dsh plugin --profile desktop add github:hyperskysail/astro-ph-researcher
```

> 本插件当前通过 `dsh.bundle` + `cordis.patch.yml` 安装；npm 包不是必需。发 npm 只是让市场显示下载量/加速安装。

## 4. Codex 版发布

Codex 插件不通过 DSH 市场上架；它已经在 `codex/` 里，和 GitHub 仓库一起分发。

### 用户安装

```bash
git clone https://github.com/hyperskysail/astro-ph-researcher.git
cd astro-ph-researcher
codex plugin marketplace add .
codex plugin add astro-ph-researcher@astro-ph-researcher-local
codex plugin list
```

只装 skills：

```bash
bash codex/install-skills.sh
# PowerShell: .\codex\install-skills.ps1
```

### 更新

```bash
codex plugin remove astro-ph-researcher@astro-ph-researcher-local
codex plugin add astro-ph-researcher@astro-ph-researcher-local
```

本机已实测 **Codex CLI 0.149.0-alpha.4.3**：

## 6. 不要做的事

- 不要直接把 `awesome-dsh-plugin` 的 README 当上传后台；它只接受 `data/plugins/*.yml` PR。
- 不要只声明 `dsh.client` 而漏掉 `dsh.bundle.patch`；市场 CI 会拒。
- 不要在 PR 里改别人的条目。
- 不要公开 `provenance/raw/session-*.jsonl` 中的本机路径/工具输出而不脱敏。
- 不要声称“市场已收录”直到 PR 合并；目前只是准备好模板。
