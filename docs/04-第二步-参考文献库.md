# 第二步：参考文献库

> 版本：v0.3.0
> 目标：把“检索到的文献”变成可长期积累、可复核、可直接引用的证据库，而不是一次性搜索结果。

---

## 1. 为什么需要独立文献库

第一步的检索结果是一次性的；研究者真正需要的是：

- **可回查**：半年前读过的结论，能找回 DOI、卷期页和当时写的总结。
- **可引用**：写论文时直接生成 BibTeX/APA/GB 7714，不再手工拼。
- **可分类**：按领域、关键词、专题（如“JWST 高红移”“引力波多信使”）组织。
- **可复核**：每条记录保留前三位作者/ORCID、单位、期刊卷期页与链接。

因此第二步把文献从“搜索结果”升级为“本地参考文献库”。

---

## 2. 数据模型

```ts
type ReferenceItem = {
  id: string;
  title: string;
  authors: string[];                 // 全部作者姓名
  authorsDetailed: { name: string; orcid?: string; affiliations: string[] }[];
  firstThreeAuthors: { name: string; orcid?: string; affiliations: string[] }[];
  affiliations: string[];            // 去重后的单位
  year?: number; date?: string;
  journal?: string; journalAbbrev?: string;
  volume?: string; issue?: string; pages?: string;
  doi?: string;                      // https://doi.org/...
  adsUrl?: string; arxivUrl?: string; scixUrl?: string; publisherUrl?: string;
  links: { label: string; url: string; kind: string }[];
  abstract?: string;
  summary?: string;                  // 分析总结归纳后的摘要成果
  keyResults: string[];              // 可引用关键结果
  notes?: string;
  tags: { fields: string[]; keywords: string[]; collections: string[] };
  citations?: number;
  addedAt: string; updatedAt: string;
};
```

存储位置：`%USERPROFILE%\.dsh\astro-ph-researcher\references.json`（原子写，250 ms 防抖）。
同一 DOI 自动去重并合并标签/总结；`id` 稳定，便于引用。

## 3. 文献来源与链接

| 用途 | 来源 | 说明 |
|---|---|---|
| 检索 | OpenAlex / Crossref / ADS / arXiv | 第一步已接入；结果带 DOI、卷期页、作者、单位、引用数 |
| 天文索引 | [SciX](https://scixplorer.org/) | 每条结果生成 SciX 检索链接（DOI 或标题），用户可跳转到具体文献 |
| 引文 | [NASA ADS](https://ui.adsabs.harvard.edu/) | 有 token 时用 ADS；无 token 时生成 ADS DOI 检索链接 |
| 预印本 | [arXiv astro-ph](https://arxiv.org/) | 结果中保留 arXiv 链接；预印本与正式版按 DOI/标题去重 |
| 期刊 | ApJ / A&A / RAA / MNRAS / PRL / PRD / JHEAP / CPC / Universe / Nature / Science | 保存 DOI 与出版社链接，具体期刊/模板数据见第三步的格式库 |
| 学位论文 | 知网（CNKI） | 无公开 API，只提供人工检索链接；不抓取、不绕过付费墙 |

> 文献库只保存元数据与用户总结，不保存付费全文；全文阅读请用 `dsh-literature` 的 PDF 阅读器或机构订阅。

## 4. 侧边栏操作

「文献库」页：

1. **保存**：在「文献」页每条结果点「保存到文献库」；或在对话中调用 `astro_reference_save`。
2. **列表**：显示标题、前三位作者（ORCID 可点）、单位、期刊卷期页、DOI/SciX/ADS/arXiv 链接、总结、关键结果、标签。
3. **分类**：编辑领域/关键词/专题（逗号分隔）；可按标签过滤。
4. **引用**：选择 BibTeX / APA / GB 7714 / MLA → 「复制引用」。
5. **导出**：`导出 BibTeX` 下载 `.bib`，可直接导入 Overleaf / JabRef / Zotero。
6. **删除**：删除单条（有确认）。

排序按 `updatedAt` 倒序；支持标题/作者/期刊/摘要/标签搜索。

## 5. 引用格式规则

### BibTeX

- 作者：`Last, First and ...`
- 标题：双花括号保护大小写
- 期刊：优先 `journal` 全名；卷 `volume`、期 `number`、页 `pages`
- DOI：去掉 `https://doi.org/` 前缀
- arXiv：`eprint` + `archivePrefix = {arXiv}`
- ADS：`adsurl`

### APA 7

`Author, A. A., & Author, B. B. (Year). Title. Journal, Volume(Issue), pages. https://doi.org/...`

### GB/T 7714-2015

`作者. 题名[J]. 刊名, 年, 卷(期): 页. DOI: ...`
作者超过 3 人时取前 3 人 + “等”；英文作者姓大写。

### MLA

`Author. "Title." Journal, vol. X, no. Y, Year, pp. Z, DOI.`

> 期刊可能有自己的参考文献样式（AASTeX、MNRAS 等）。第三步写作时会以目标期刊的作者指南/Overleaf 模板为准；BibTeX 只是通用输入。

## 6. 分类与“可引用总结”

建议每条文献写三层：

1. **一句话结论**（可引用）：作者用什么数据/方法得到了什么结果。
2. **关键结果**（2-4 条）：带数值、误差、样本量、波段；只写摘要/全文中确实有的。
3. **局限/我的判断**：样本、方法、假设、与其它文献冲突；明确标注“我的推断”。

领域建议：恒星、星系、宇宙学、多信使天文学、太阳物理、系外行星、天体测量、星际介质、仪器/方法。
关键词建议：源类型（AGN、GRB、FRB）、信使（中微子、引力波、宇宙线）、望远镜（JWST、Fermi、IceCube）、方法（神经网络、MCMC、引力透镜）。

## 7. API 与工具

工具：

- `astro_reference_save`：保存/合并一条文献（可直接传检索结果）。
- `astro_reference_list`：按 query/field/keyword/tag/collection 过滤。
- `astro_reference_update`：修改总结、关键结果、标签、笔记。
- `astro_reference_cite`：生成 BibTeX/APA/GB 7714/MLA。
- `astro_reference_export`：导出 BibTeX。

HTTP（客户端使用）：

- `GET /api/astro-ph-researcher/references`
- `POST /api/astro-ph-researcher/references`
- `PATCH/DELETE /api/astro-ph-researcher/references/:id`
- `POST /api/astro-ph-researcher/references/cite`
- `GET /api/astro-ph-researcher/references/export?format=bibtex`

---

## 8. 已知边界

- 不保存付费全文；摘要/总结来自 API 与用户输入。
- 作者单位/ORCID 依赖 OpenAlex/Crossref 元数据；缺失时留空，不编造。
- 引用格式是通用实现；目标期刊的特殊要求（如 AASTeX 的 `\bibitem` 样式）需在 LaTeX 模板中转换。
- 不提供云端账户同步；文献库在本地，可通过导出/共享文件迁移。
- 删除是不可逆的；重要库请定期备份 `references.json`。
