## 1. 为什么一直出现 “cannot edit / retry”

实际报错是：

```text
Error: cannot edit "…": file changed since it was read — re-read the file, then retry
FsError FS_STALE_VERSION
```

这不是磁盘没权限，也不是 DSH 文件策略阻止写入（当前策略是 `danger-full-access`）。原因是：

1. 我用 `read` 读了一个文件，随后**同一个文件又被改动**，再用旧的读取版本去 `edit`，文件系统版本守卫拒绝覆盖。
2. 改动来源包括：
   - 我自己的批量脚本（例如把 `v0.3.0 → v0.4.0`、`api-v5 → api-v6` 用 Python 一次性替换多个文件）；
   - 多个 teammate 同时在写 `data/`、`research/`、`docs/`；
   - 插件热重载/配置变更期间，部分文件被再次 touch。
3. 于是出现“读 → 改别处 → 再 edit 旧文件”的 stale 版本，必须重读再改。会话里能检索到 **38 条** `FS_STALE_VERSION` 事件，集中在 README、lib/index.js、lib/client.js、docs/02、docs/03、demo/template、test/host-smoke 等文件。
4. 另外还有几类不同的错误，不应混为一谈：
   - `ENOTEMPTY`：测试清理临时目录时后台保存还没结束（已加等待/重试）；
   - HTTP 404：插件热重载后旧路由实例占着前缀，新实例注册不上；后来把 API 前缀升级到 v6 绕开，**但留下旧 v1–v5 实例**，干净重启才会清掉；
   - `old_string` 不匹配：批量替换后原文变了，`edit` 自然找不到；同样靠重读解决。

**结论：** retry 主要是“读后文件被改”的版本冲突，不是写不进去。最终文件通过了语法、JSON、单元测试和在线 API 校验；但这个过程确实低效，应该一个文件一个 writer、避免边跑批量替换边 edit、teammate 写 `data/` 时不要同时改同一文件。

## 3. 没有完成 / 不能声称完成的部分

### 3.1 书中 Python 代码不是原书代码

- 我**没有拿到原书全文/电子版**，只拿到 NADC 出版消息（含前言/章节结构）和豆瓣书目（出版信息）。
- 插件里的 Python 是**独立编写的标准实现**，用来对应方法，不是从书中抄录的代码。
- 因此：方法/统计的“覆盖”是可靠的；但“书中每一段代码都收进来了”不成立。若需要与书中代码逐段对齐，需要你提供 PDF/扫描/截图，我再做章节级核对（仍只做必要摘录，不整本复制）。

### 3.2 书籍分析不是逐页精读

- `docs/09` 的结构、统计主线、优缺点，依据的是前言和目录，不是逐页阅读。
- 书中的公式符号约定、小节编号、习题/例子细节，未逐页核对；以原书为准。

### 3.3 “云端保存/共享”没有做

- 高校格式、期刊格式、个人工作流都是**本地文件**：
  - `thesis-formats.custom.json`
  - `workflows.json`
  - `references.json`
- 提供的是 JSON 格式包导出/导入；没有服务器、账号、云端同步。
- 之前文档已写明“当前版本不提供云端账户同步”，不能把“导出格式包”说成“云端”。

### 3.4 UI 没有经过真实浏览器点击验收

- 我验证了：client bundle 能被 DSH 加载、slot 注册 active、源码语法/注册测试通过。
- **没有**在带登录态的 DSH Web GUI 里逐个点击「数据 / 统计原理 / 设备 / 保存工作流」并截图确认。
- 当前页面可能仍是旧 client bundle；需要刷新页面。刷新后若没有「数据」页，需重启 DSH（或检查 profile 是否加载了最新 bundle）。

### 3.5 没有真正执行观测数据管线

- Chandra/CIAO、Fermi/fermipy、IceCube/SkyLLH、LIGO/GWpy 等：插件给的是**官方入口、软件、步骤、建议**，没有替你下载真实数据、跑完整分析、产出科学结果。
- 这是有意的边界（避免替你伪造分析），但如果你要的是“跑通一条真实数据分析”，那还没做。

### 3.6 设施是 curated 30 个，不是“全世界全部”

- 30 个覆盖主流空间/地面/多信使设施，但不是穷举。
- 研究报告中明确列出未覆盖：Spitzer、Herschel、Euclid、KM3NeT、CSST 等；后续可同 schema 增补。
- 25/30 链接在线验证通过；5 个（H.E.S.S.、eROSITA DR1、LHAASO、SKA、ELT）因官网不可用/反爬标 `verified:false`。

### 3.7 其他缺口

- 参考文献库只做导出/引用，**没有做 BibTeX 导入**（用户“上传/改正归类”目前靠网页编辑，不是导入 .bib）。
- 期刊 SCI 收录状态无法精确判定；只用文章类型/期刊/引用数近似。
- 知网没有公开 API，只给人工链接。
- 安装是 junction + bundle 手动方式，**没有在全新 profile 上做干净安装测试**。
- 插件热重载留下了旧 API 前缀实例（v1–v5），当前 v6 可用，但干净重启才会清掉。

## 5. 建议的下一步（按优先级）

1. **先验收 UI**：刷新页面 → 打开「数据」→ 点四个子页 → 保存一个工作流 → 删除。若空白/报错，把截图或 console 错误发我。
2. **补原书对齐**：提供 PDF/扫描/目录照片，做章节级核对；代码只做必要摘录/改写，不整本复制。
3. **决定是否要“真跑一条管线”**：选 Chandra 或 Fermi，下载一个小样本，跑官方教程到出图；这一步需要安装 CIAO/HEASoft/fermipy，环境较重。
4. **云端**：如果确实要多人共享，需要确定后端（对象存储/数据库/账号），不是当前本地 JSON 能冒充的。
5. **干净安装测试**：新建 profile 或临时目录，按 README 从零安装一次，确认不是只靠当前 junction 生效。

## 6. 结论

- 插件、数据、Skill 的**代码层与数据层**确实完成并通过测试；不是空壳。
- **没有偷吃大米**：没有编造“已读全书/已跑管线/已上云/已逐个点击 UI”。未完成的点已列在上。
- 最大的两个真实缺口是：**原书代码/正文对齐**、**真实 UI 点击与真实数据管线验收**。
