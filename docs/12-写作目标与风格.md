# 12 · 写作目标与叙述风格

> 版本：2026-10-22
> 数据：`data/writing-goals.seed.json`（10 个目标）
> 相关 skill：`astro-writing-goals`、`astro-discovery-writing`、`astro-critical-writing`、`astro-incremental-method-writing`
> 原则：风格是对已发表论文**修辞结构**的归纳，不复制原文；示例论文只作结构参考，引用前核验 DOI 与结论。

---

## 1. 为什么要按“目标”分风格

同一组数据，写成“首次发现”“独立确认”“批判重分析”“跟进增量”会被审稿人用完全不同的标准衡量：

- discovery 需要 5σ 级别的证据与替代解释排除；
- confirmation 需要独立数据/独立管线，而不是同一数据重跑；
- refutation 需要先复现原分析，再定位具体问题，语气不能人身化；
- incremental 必须诚实承认增量，不能包装成 first discovery；
- null-limit 的价值在“排除了什么”，不是“我们没看到”；
- method/software 的验收是基线与可复现，不是漂亮结果；
- survey/catalog 的核心是选择函数、完备度、纯度与访问；
- theory/model 的核心是假设透明、可证伪；
- multimessenger 的核心是关联显著性，不是单个信使的显著性；
- review 的核心是问题结构与共识/争议/未知的区分。

插件现在把“目标”作为项目的显式字段 `goalId`，写作提示词自动注入目标卡；没有目标时用通用学术风格。

## 2. 十个目标

| id | 目标 | 核心姿态 | 常见期刊 |
|---|---|---|---|
| discovery | 首次发现/新现象 | 强主张，但限定在数据覆盖范围 | ApJL / Nature / Science / PRL |
| confirmation | 独立确认/复现 | 审慎肯定，强调独立数据 | ApJ / MNRAS / A&A |
| refutation | 批判/反驳/重分析 | 对事不对人；先复现再定位问题 | MNRAS / ApJ / A&A / RNAAS |
| incremental | 跟进/增量更新 | 诚实承认增量，价值在更准/更全 | ApJ / MNRAS / A&A / AJ |
| null-limit | 零结果/上限 | 把“没看到”转成“排除了什么” | ApJ / MNRAS / PRD |
| method-software | 方法/软件/管线 | 可复现、有基线、有失败模式 | JOSS / A&C / ApJS / PASP |
| survey-catalog | 巡天/星表/数据发布 | 选择函数、完备度、纯度、访问 | ApJS / A&A / AJ |
| theory-model | 理论/模型解释 | 假设透明、预言可证伪 | ApJ / MNRAS / PRD / JCAP |
| multimessenger | 多信使/快速响应 | 关联显著性优先 | ApJL / Nature / Science / PRL |
| review-perspective | 综述/观点/路线图 | 问题导向，区分共识/争议/未知 | ARA&A / Nature Reviews / Physics Reports |

每个目标包含：`whenToUse`、`coreStance`、`noveltyClaim`、`evidenceThreshold`、`titlePatterns`、`abstractMoves`、`introMoves`、`resultsMoves`、`discussionMoves`、`conclusionMoves`、`claimVerbs`、`hedging`、`reviewerRisks`、`journalFit`、`prompt`、`exemplars`。

## 4. 如何选择

1. 先写下“本文一句话贡献”。
2. 对照第 2 节：是第一次、确认、反驳、增量、上限、方法、数据、理论、多信使还是综述？
3. 用目标卡的 `evidenceThreshold` 检查证据；不够就**降级**：
   - discovery → confirmation / incremental
   - confirmation → incremental
   - refutation → null-limit
   - multimessenger 确认关联 → 仅时间/空间关联
4. 用 `journalFit` 选目标期刊，再用期刊格式数据卡确认模板与引用风格。
5. 用 `astro_writing_handoff(mode="outline")` 生成 3 个标题变体 + 摘要骨架。
6. 用 `mode="draft"` 逐节写；用 `mode="audit"` 做投稿前红队。

## 5. 本轮的优化策略（复盘后补的）

| 优化 | 实现 |
|---|---|
| **目标感知** | 项目 `goalId` → 写作提示词自动注入目标卡 |
| **证据-主张校准** | 每个目标有 `evidenceThreshold`；提示词要求证据不足时降级 |
| **标题/摘要 A/B** | 每目标给 `titlePatterns` + `abstractMoves`；要求 3 个标题变体 |
| **投稿前审计** | `mode="audit"`：主张-证据表、风格-证据匹配、引用意图、10 个审稿人问题、三档修改建议 |
| **期刊匹配** | `journalFit` + 现有 14 期刊格式数据；避免把 discovery 投到只收 incremental 的期刊 |
| **引用意图** | audit 要求标注“支持/扩展/反驳”，防止误引与漏引原始文献 |
| **审稿人红队** | 每目标列 `reviewerRisks`；skill 给 10 问 |
| **风格锁定** | 项目创建时选目标；后续可改，提示词随之变化 |
| **不伪造** | 示例论文只作结构参考；不复制摘要/句子；PDF/DOC 未解析就不假装读过 |

## 6. 已知边界

- 风格归纳基于公开摘要/论文结构与领域写作经验，不是对海量语料的统计训练；不能保证审稿人一定接受。
- 示例论文只覆盖部分目标；没有为每个目标找 10 篇样本。
- “目标”不是期刊录取预测器；期刊匹配只是写作/投稿建议。
- 语言风格仍要遵守目标期刊的 author guidelines；`astro-format-library` 与 `astro_thesis_format` 负责格式，不负责科学判断。
- 所有强主张仍由作者对数据、引用与结论负责；插件只做提示与审计。
