## 1. v2 一句话目标

把写作从“AI 一次生成一篇”改成：

```text
选目标 → 给文献/证据打分 → 逐节 AI 起草 → 作者手动微调
→ 逐节检查 → 作者显式确认 → 锁定 → 生成可审计稿
```

做到三件事：

1. **可量化**：文献、章节、主张都有分项评分和评分依据；
2. **可微调**：DSH 内可对 AI 写好的段落做作者级编辑、接受/拒绝、回退；
3. **可确认**：每一节、每个关键主张都有作者本人确认记录，AI 不能代替点击。

## 2. 打分系统

### 2.1 文献评分（Literature Score）

不要只给一个“总分”。建议 6 个维度，0–5 分，再给加权总分：

| 维度 | 看什么 | 示例问题 |
|---|---|---|
| 相关性 | 与当前研究问题/章节的匹配 | 它回答的是同一个科学问题吗？ |
| 证据强度 | 数据量、显著性、系统误差、独立验证 | 结论是否被数据支撑？ |
| 方法严谨性 | 方法可复现、假设透明、基线合理 | 能否按文中步骤复现？ |
| 可复现性 | 数据/代码/参数是否可获取 | 有无公开数据、代码、版本？ |
| 发表可信度 | 同行评审、期刊/会议、作者/机构 | 是否正式发表？是否有争议？ |
| 时效/语境 | 是否最新、是否被后续工作修正 | 有没有更新版本或反驳？ |

输出：

```json
{
  "paperId": "doi:...",
  "rubricVersion": "lit-v2.0",
  "scores": {
    "relevance": 5,
    "evidence": 4,
    "method": 4,
    "reproducibility": 3,
    "venue": 5,
    "currency": 4
  },
  "weighted": 4.25,
  "reasons": ["..."],
  "flags": ["sample small", "no public code"],
  "authorOverride": null
}
```

**纪律：**

- 分数是**辅助排序**，不是“论文质量真理”；
- 每个分数必须能指向题录/摘要/全文中的证据；
- 作者可覆盖分数，但覆盖要留记录；
- 不允许把“引用数高”直接当质量高；
- 预印本、会议、正式期刊要分栏显示。

### 2.2 文章各部分评分（Section Score）

每个章节单独评分，0–100 或 0–5，含“为什么”：

| 维度 | 标题/摘要 | 引言 | 方法 | 结果 | 讨论 | 结论 |
|---|---|---|---|---|---|---|
| 主张-证据一致 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 新颖性校准 | ✓ | ✓ |  | ✓ | ✓ |  |
| 引用覆盖/意图 |  | ✓ | ✓ |  | ✓ | ✓ |
| 数值/单位/图一致 | ✓ |  | ✓ | ✓ | ✓ | ✓ |
| 可复现性 |  |  | ✓ | ✓ |  |  |
| 风格-目标匹配 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 语言/结构 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

输出：

```json
{
  "projectId": "proj_...",
  "section": "results",
  "rubricVersion": "section-v2.0",
  "scores": { "claimEvidence": 82, "noveltyCalibration": 70, "citation": 65, "consistency": 90, "reproducibility": 60, "styleFit": 85, "language": 78 },
  "overall": 76,
  "blockers": ["图 3 的误差棒未在正文说明", "结论句比数据强"],
  "suggestions": ["把 'proves' 改为 'is consistent with'"],
  "authorOverride": null,
  "scoredAt": "...",
  "scoredBy": "ai-advisory"
}
```

**关键：** 分数必须可解释；没有证据链的分数不允许写入“作者确认”记录。

### 2.3 评分标准（Rubric）要求

- 每个维度有 **0/1/2/3/4/5 锚点描述**；
- 评分器版本号固定（如 `section-v2.0`）；
- 同一稿件改稿后可重评，保留历史；
- 作者可标记“不同意该评分”，写理由；
- 导出时保留评分时间、rubric 版本、AI/人工来源。

## 3. 逐节写作（Section-by-section）

### 3.1 状态机

```text
todo
  → ai_draft
  → author_editing
  → needs_evidence
  → ready_for_review
  → author_confirmed
  → locked
```

规则：

- `author_confirmed` 只能由**作者本人**点击；
- 没有确认不能进入下一节（可配置“允许先写下一节但不可导出”）；
- `locked` 后修改必须重新打开并重新确认；
- 每节有独立的 `contentHash`，确认绑定该 hash；
- 修改后 hash 变化 → 旧确认自动失效，需重新确认。

### 3.2 建议顺序

1. 研究问题 + 一句话贡献
2. 目标期刊/学校格式 + 写作目标
3. 证据/数据清单
4. 标题 + 摘要
5. 引言
6. 数据与方法
7. 结果（图/表逐张核对）
8. 讨论
9. 结论
10. 参考文献 + 引用意图
11. 格式检查
12. 最终作者确认

每一步都有：

- 输入（文件/数据/引用）；
- AI 产出；
- 作者编辑；
- 检查清单；
- 评分；
- 作者确认；
- 锁定/回退。

### 3.3 每步的交付物

| 步骤 | 交付物 | 必须确认 |
|---|---|---|
| 标题/摘要 | 3 个标题变体 + 摘要骨架 | 主张强度、数字、期刊匹配 |
| 引言 | 缺口→贡献→路线 | 引用是否支持每句 |
| 方法 | 数据/仪器/软件/参数 | 可复现性 |
| 结果 | 图/表/统计量 | 数字与图一致 |
| 讨论 | 机制/替代解释/限制 | 不超出数据 |
| 结论 | 3–5 条结论 | 与摘要/标题一致 |
| 引用 | 引用意图表 | 无虚构/误引 |
| 格式 | 检查清单 | 目标格式 |

## 4. DSH 内的人工微调

### 4.1 编辑方式

- **段落级编辑**：直接改 AI 文本；
- **块级接受/拒绝**：AI 建议以 diff 展示，作者逐块接受或拒绝；
- **改写强度**：保持原意 / 精简 / 加强论证 / 降低主张；
- **锁定**：作者可锁定一段，AI 后续不得改；
- **回退**：每次 AI/作者修改都有版本；
- **对比**：AI 草稿 vs 作者版本 vs 上一版；
- **标记**：“这是我写的”“这是 AI 写的，我已核对”“此处需要证据”。

### 4.2 不能做的事

- AI 不能自动把作者段落改掉；
- AI 不能代替作者点“确认”；
- AI 不能删除作者手写内容而不留 diff；
- AI 不能把未核验引用标成“已确认”。

### 4.3 建议 UI

```text
[章节] 结果
[状态] 作者编辑中 · 未确认
[AI 草稿]  [作者版本]  [对比]
┌──────────────────────────────────────┐
│ 3.2 光变曲线拟合                       │
│ 我们采用...          [编辑] [锁定]     │
│ AI 建议：把 "proves" → "is consistent" │
│ [接受] [拒绝] [查看理由]               │
└──────────────────────────────────────┘
[检查清单] □ 数字与图一致 □ 误差已说明
[作者确认]  ☐ 我已核对本节数据、引用与措辞
```

## 5. 作者确认体系（Author Confirmation）

### 5.1 确认记录

每条确认至少包含：

```json
{
  "confirmationId": "conf_...",
  "projectId": "proj_...",
  "section": "results",
  "contentHash": "sha256:...",
  "rubricVersion": "section-v2.0",
  "scoreSnapshot": 76,
  "checklist": {
    "numbersMatchFigures": true,
    "citationsVerified": true,
    "claimsSupported": true,
    "styleGoalApplied": true
  },
  "confirmedBy": "author",
  "confirmedAt": "2026-10-22T...",
  "authorNote": "图 3 误差棒已补；结论句已降级",
  "aiDraftHash": "sha256:...",
  "diffSummary": "3 处作者修改，2 处接受 AI 建议，1 处拒绝"
}
```

### 5.2 确认规则

- **只能是作者本人**：UI 点击 + 可选输入确认短语；
- 确认绑定 `contentHash`；内容变了确认失效；
- 每节确认后 `locked`；解锁需记录原因；
- 最终稿需要“全文确认”，列出所有章节确认状态；
- 导出时附 `confirmation-ledger.json` 与人类可读的 `confirmation-report.md`；
- AI 不允许写 `confirmedBy: "author"`，只能写 `ai-advisory`；
- 可选：多作者时每人一条记录（v2 先做单作者）。

### 5.3 最终确认清单

- [ ] 标题/摘要/结论主张一致
- [ ] 所有数字能指向图/表/数据
- [ ] 所有引用已核验，无虚构 DOI
- [ ] 图表误差/单位/样本量已说明
- [ ] 方法可复现（数据/代码/参数）
- [ ] 目标期刊/学校格式已检查
- [ ] 写作目标与证据强度匹配
- [ ] 我知道哪些段落由 AI 起草、哪些由我改写
- [ ] 我本人对最终内容负责

## 6. 标准化与精细化

### 6.1 固定 schema

- `lit-score.schema.json`
- `section-score.schema.json`
- `confirmation.schema.json`
- `draft.schema.json`
- `rubric-v2.json`

### 6.2 可审计导出

```text
project/
  draft.md
  scores/
    literature.json
    sections.json
  confirmations/
    confirmation-ledger.json
    confirmation-report.md
  diffs/
    section-01.diff
  audit/
    rubric-version.txt
    ai-vs-author.json
```

### 6.3 质量门禁

- 没有作者确认 → 不能标记“可投稿”；
- 分数低于阈值 → 只提示，不自动阻断（作者可覆盖，但要写理由）；
- 引用未核验 → 不能进入“最终确认”；
- 关键数字无图/表来源 → 标红；
- AI 文本占比可显示，但不作为“好坏”唯一标准。

## 9. 风险与边界

- **分数不是真理**：AI 评分可能偏差；必须可解释、可覆盖、保留人工记录。
- **确认不是法律担保**：作者确认是“我已核对”的声明，不替代同行评审/伦理审查。
- **AI 不能替作者负责**：最终科学责任仍在作者。
- **隐私**：作者手稿、未发表数据默认本地；不上传服务器。
- **可复现**：评分 rubric、模型版本、时间、输入摘要都要记录。
- **不破坏 v1**：v1 项目数据只读兼容，升级需显式迁移。
