# 天文分析代码编写规范

代码的验收标准不是“能跑”，而是：别人拿到数据、环境文件与运行命令后，能得到同样的数字和同样的图。

## 一、目标与交付定义

每次编码任务先写清四件事：输入数据是什么、要回答什么科学问题、方法出处是哪篇文献、输出是哪几个数值/图/表。交付物固定包含：

1. 可运行的代码与入口命令；
2. 环境文件（`requirements.txt` 或 `environment.yml`，版本由实际安装结果回写）；
3. 数据字典（列名、单位、缺失值、样本量、筛选后样本量）；
4. 结果图（PDF）与一段结果说明（含数值、不确定度、失败项）。

角色适配只改变解释深度：本科生需要逐步注释与最小示例；研究生需要完整流程与测试；研究员/教授需要方法溯源、系统误差与收敛诊断。

## 二、开工前先读数据与文献

在写第一行分析代码前，输出一份“数据契约”：

- 文件格式、行数、列名、每列单位、物理含义、缺失值编码；
- 样本量 N、有效样本、重复/异常值、极端值；
- 观测/模拟条件：仪器、波段、曝光、分辨率、定标版本；
- 方法出处：公式与算法的 DOI，符号定义与适用条件；
- 与文献报告值的预期量级（用于后面的量级检查）。

缺什么就写“缺失”，不要用默认列名猜测。用户只说“拟合一下”时，先确认模型、似然、先验与单位，再写代码。

## 三、环境与依赖

用 DSH 的 `pyenv_*` 工具管理环境，不要在 shell 里直接跑 `pip` 或 `python -m venv`：

1. `pyenv_discover` 查现有环境；
2. `pyenv_create(name=".venv")` 建环境；
3. `pyenv_install(packages=[...])` 安装依赖；
4. 用工具返回的解释器路径运行脚本（Windows 为 `<venv>\Scripts\python.exe`，Linux 为 `<venv>/bin/python`）。

标准栈按需选择，避免无必要依赖：

| 用途 | 包 |
|---|---|
| 数组与数值 | `numpy`、`scipy` |
| 单位、常数、坐标、宇宙学、FITS | `astropy`（`astropy.units`、`astropy.constants`、`astropy.coordinates`、`astropy.cosmology`、`astropy.io.fits`、`astropy.table`） |
| 绘图 | `matplotlib` |
| MCMC（马尔可夫链蒙特卡洛） | `emcee` 或 `zeus`；后验图用 `corner` |
| 在线星表/归档 | `astroquery`（按需，注明数据源与查询日期） |

记录实际安装版本，写入环境文件；不要写“最新版”这类不可复现的约束。

## 四、项目结构

```text
project/
├─ config.py          # 路径、常数、筛选阈值、随机种子
├─ io.py              # 读数据、列名/单位校验
├─ preprocess.py      # 清洗、切割、选择函数
├─ model.py           # 物理模型、公式、单位
├─ inference.py       # 拟合/MCMC/误差传播
├─ plots.py           # 出图（PDF）
├─ tests/             # 合成数据、边界、回归
├─ requirements.txt
└─ README.md          # 运行命令、数据字典、结果说明
```

硬性要求：随机种子集中在 `config.py`（如 `SEED = 20261022`，`rng = np.random.default_rng(SEED)`）；所有路径来自配置；入口用 `python -m project.run` 或明确的 `python run.py --config ...`；不在 notebook 与脚本之间复制两套逻辑。

## 五、单位、常数与公式

- 输入输出一律带单位；优先 `astropy.units`。量纲不合法时让程序报错，而不是静默换算。
- 物理常数用 `astropy.constants`（如 `const.c`、`const.G`、`const.M_sun`），不写来源不明的魔法数；确需数值时注明来源与版本。
- 每个公式在 docstring 写：公式、符号表、单位、适用条件、文献 DOI。推导未核实的公式标 `TODO(verify)`，不得当既成事实使用。
- 边界与物理可行性检查至少覆盖：物理量（光度、质量、半径、温度）非负；测量流量允许噪声导致的负值，但必须单独标注；红移 `z > -1`；概率在 `[0, 1]`；频率/波长在仪器覆盖范围内。
- 单位换算集中在 `io.py`/`model.py` 的边界处，不在公式中间零散乘系数。

```python
import astropy.units as u
from astropy.constants import c

flux = flux_value * u.Jy
lum_nu = 4 * np.pi * d_L**2 * flux
lum_nu = lum_nu.to(u.erg / u.s / u.Hz)   # 光度密度；bolometric 需对频率积分
nu = (c / wave).to(u.GHz)
```

宇宙学计算写明所用的 cosmology（如 `Planck18`）与参数来源；换 cosmology 必须重跑并对比。

## 六、数据读取与筛选

- 读入后先打印列名、dtype、单位、缺失值比例、样本量；FITS 数据同时检查头文件关键关键字。
- 每个筛选条件单独成函数并记录通过数，输出 cut-flow（筛选流程）表：`原始 N → 质量 cuts → 信噪比 → 红移/星等范围 → 最终 N`。
- 缺失值处理必须显式：删除、插补还是保留并加权；说明理由与影响。
- 涉及流量限制或巡天数据时，说明选择函数与 Malmquist 偏差；不能把截断样本当完整样本。
- 不静默丢数据：任何 `dropna()`、异常值剔除、坐标匹配失败都要计数并写进日志。

## 七、统计与推断

- 误差要区分统计误差与系统误差；给出置信区间、置信水平与误差传播方式。
- 上限（upper limit）用明确的置信水平与计算方法（如似然比、贝叶斯上限），不要用 `0 ± 0` 冒充。
- MCMC 写明似然、先验、参数化与初值；报告接受率、自相关时间；多链时报告 `R̂` 与有效样本量（ESS）。收敛不达标就加步数或改参数化，不能直接出图。
- 模型比较说明指标（如 ΔAIC/BIC、贝叶斯因子）及其假设；多重比较或盲搜要说明 look-elsewhere effect。
- 不 p-hacking：不反复调参直到显著；不隐藏失败拟合；不把“未检出”写成“不存在”。
- 结果至少做一次量级/符号/极限检查（如 `z→0`、`M→0`、高信噪比极限）。

## 八、图表规范

- 论文图保存为 PDF 矢量；位图只用于必须的截图/图像数据。
- 字号足够（正文图建议 ≥8–10 pt），线宽、标记、误差棒清晰；不使用背景网格（除非期刊模板要求）。
- 色盲友好配色；同一物理量在不同图中用同一颜色/标记；图例与坐标轴单位完整。
- 误差棒、上限箭头、置信区间要画出来；图注自含（样本、仪器/波段、筛选、单位、置信水平）。
- 图注与正文数字一致；图中不出现未定义的缩写。目标期刊的作者指南/模板用 `astro_format_library(action="journals", query="ApJ")` 查入口，再打开官网核对图表要求；插件索引不能替代官网。

## 九、测试与运行

- 合成数据测试：构造已知参数的数据，验证能否回收参数（在容差内）。
- 边界测试：空输入、单点、全缺失、极端值、单位错误必须给出明确错误。
- 回归测试：与文献报告值或上一版结果对比，记录差值与容差。
- 每次交付前实际运行测试与主流程；失败就报告失败位置、错误信息与已完成步骤，不谎称成功。
- 长任务用后台作业并记录输出；生成结果后核对文件大小、行数、图像是否为空。

## 十、引用与可复现

- 代码头注释写清：方法文献 DOI、公式来源、数据来源与下载日期、软件版本。
- 引用格式化：先用 `astro_reference_save` 把方法/数据文献存入库，再用 `astro_reference_cite(id, style="bibtex")`；LaTeX 工程用 `astro_reference_export(ids)` 生成 refs.bib，不手写条目。
- README 写最短复现路径：环境创建 → 安装 → 运行命令 → 预期输出（文件名、关键数值范围）。
- 输出结果目录带时间戳或配置哈希；配置文件随结果一起保存。
- 用 `astro_literature_analyze` 整理方法相关文献的数据、方法/公式与可复现性信息，再据此写代码；不要把摘要里的方法当成已验证实现。

| 工具 | 用途 |

| `pyenv_discover` / `pyenv_create` / `pyenv_install` / `pyenv_uninstall` | 创建、安装、清理项目环境；不使用 shell 里的 pip |
| `pwsh` / `wsl` | DSH 的 shell 工具：Windows 用 pwsh，WSL/Linux 用 wsl |

| `astro_format_library` | 查目标期刊的作者指南/模板/引用风格入口 |
| `astro_literature_analyze` | 核对方法/公式出处与可复现性（仅题录+摘要） |

## 十二、禁止事项

1. 伪造运行结果、拟合参数、图像或“测试通过”。
2. 静默删数据、改列名、改单位而不告知。
3. 使用来源不明或未经验证的公式/常数。
4. 用默认参数掩盖模型选择，或只报最优值不报不确定度。
5. 把未收敛的 MCMC 结果当最终结果。
6. 把合成数据结果说成真实观测结果。
7. 安装与任务无关的依赖，或把凭据写进代码/日志。
8. 在未运行的情况下声称“已复现”。

## 十三、质量检查清单

- [ ] 数据契约（列名/单位/缺失/样本量）已输出并核对
- [ ] 公式、常数、cosmology 均有出处
- [ ] 量纲检查与物理边界检查通过
- [ ] 筛选有 cut-flow 表，无静默丢数据
- [ ] 误差、置信区间/上限、收敛诊断齐全
- [ ] 图表为 PDF、字号足够、图注自含、数字与正文一致
- [ ] 至少一个合成数据测试与一个边界测试通过
- [ ] 环境文件与解释器版本已记录
- [ ] README 能按命令复现关键结果
- [ ] 失败项已如实报告，无伪造结果

## 十四、模板句式

- 代码头注释：“Method: {Author et al. year, DOI}；公式 {编号}；数据：{来源, 下载日期}；软件：Python {版本}, astropy {版本}。”
- 结果说明：“在 {N} 个样本上，{参数} = {值} ± {统计误差}（统计）± {系统误差}（系统），{置信水平}；与 {文献值} 的偏差为 {差值}。”
- 失败报告：“主流程在 {步骤} 失败：{错误信息}。已完成的检查为 {列表}；未生成 {输出}，不将中间结果作为最终结果。”
- 复现说明：“运行 `{命令}`，预期生成 `{文件}`，关键数值应在 `{范围}` 内；随机种子 `{SEED}`。”
